# 2026-11-04: the QA gate becomes concurrent, pinned and enforced on push

## What happened

The fleet audits of 2026-11-04 found the same three failures in every repo, zotero-core included:

- **A sequential `qa` hid failures.** The suite justfile ran `qa: _submodules lint sprawl test`.
  `just` stops at the first failing recipe, so once `lint` went red, ty, the import contracts,
  vulture, codespell and pytest never ran inside `just qa`. Lint was red here from `539f3fe`
  (2026-08-24): two E501 lines it added, in `application/services/context.py` and
  `interfaces/cli.py`. Nine commits landed on that red gate before this change.
- **No hooks.** There was no `.pre-commit-config.yaml`, and no hooks were installed, so nothing
  ran the gate before a commit or a push.
- **Versions floated.** `ruff>=0.6` resolved to 0.16.3; a lock upgrade could turn lint red with
  no code change.

## What changed

- `just qa` (in the suite justfile, `../justfile`) is the fleet's concurrent recipe: lint,
  fmt-check, types, layers, dead, spell and test start at once, each PID is waited on alone, the
  output is replayed in order and the summary names every failing check (`QA FAILED: ...`).
  The old `lint` recipe (ruff + ty + lint-imports) split into `lint`, `types` and `layers`;
  `sprawl` split into `dead` and `spell`. `format` became `fix`, which also runs `ruff format`
  and is never part of the gate.
- Pins: `ruff==0.17.2` (was `>=0.6`), `ty==0.0.88` (was `==0.0.55`; the bump raised no new
  diagnostics). The ruff-pre-commit `rev` is `v0.17.2` to match.
- `.pre-commit-config.yaml` in core: whitespace/yaml/toml/large-file/private-key/merge-conflict
  hooks, the ruff fixers and gitleaks on commit, `just qa` on pre-push. Hooks installed with
  `uvx pre-commit install`. `just` walks up from `core/` to the suite justfile, so the pre-push
  hook works from this repo.
- `ruff format` was adopted, reversing a recorded decision. The justfile and README declined
  it because the formatter would flatten meaningful layout: the CRUD grouping of `__all__` and
  hand-aligned verb call sites. Measured with ruff 0.17.2 before adopting: the formatter keeps
  the `__all__` grouping (it adds one blank line above the list), and no aligned call site in
  `src/` changed. The only flattened alignment was three assignments in a README code sample.
  The tree was formatted in one format-only commit.
- Base ruff rules: `W`, `C4` and an explicit `TID252` joined the select list (`TID` was already
  on).
